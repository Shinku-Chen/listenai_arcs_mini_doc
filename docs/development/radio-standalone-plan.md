# 网络电台「固件化」实施计划（radio-standalone）

> 决策（2026-10-16）：**放弃小应用路线**，把网络电台**完整实现进固件**，
> **移除 AI 助手（语音唤醒/对话/云链路）**，设备**开机直接进入网络电台**。
> 产物 = 固件镜像（新分支 `feat/radio-standalone`），像 AI Passport 那样"新分支提交固件"。

## 一、目标与非目标

| 目标 | 非目标 |
|---|---|
| 开机即进网络电台，按键即可换台/调音量/定时 | 不再提供小应用/小程序安装与管理 |
| 电台功能完整：内置 6 台 + 在线地区目录 + 音量 + 睡眠定时 + 电量显示 | 不再提供 AI 对话、语音唤醒、云端会话 |
| 固件可独立构建、可整包烧录 | 不追求保留原厂全部设置页 |

## 二、⚠️ 一个必须先定的冲突

**扫码配网（二维码）目前属于助手 UI**（`apps-ui/apps/llm/` 的 info/qrcode 页面）。
"移除 AI 助手" 与 "之前要求的保留扫码配网" **冲突**，需二选一或折中：

| 方案 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** | 保留**一个最小配网页**（只做二维码配网 + 状态显示），其余助手页面/逻辑全部摘除 | 需要把配网页从 llm 应用里抽出来独立 |
| B | 完全移除助手，配网改用 **SmartConfig / SoftAP** | 要新写配网流程，工作量大 |
| C | 完全移除助手且**不做配网**（Wi-Fi 凭据预置/出产烧录） | 设备换网需重新烧录 |

## 三、实施步骤（每步都可单独构建 + 真机验证）

1. **收音机 UI 完整化**（在已有 `apps/arcs-mini/radio_ui/` 骨架上继续）
   - 顶栏（CH / 时钟 / 信号 / 电量填充）、台名、描述
   - 刻度盘面板 `22,78,196×54`：41 根刻度（长/中）、轨道、指针 3×22（**直接跳动、无缓动无光晕**）
   - 电平条面板 `13,138,214×46`（先拟态，后续接真实 RMS）
   - 状态行（中心 y=196，城市右对齐）、提示行（y≈220）
   - 菜单页：电台列表 / 城市 / 音量 / 睡眠定时 / 恢复内置 / 继续播放（列表每帧文字 ≤8 段）
2. **播放链路 + 数据**
   - 音频：`app_player_*`（复用 mini-app 音频实现路径，已实测可播 http 直播流）
   - 内置 6 台（中国之声/怀旧音乐/清晨音乐/两广之声/羊城交通/第一财经，qingting 64k mp3）
   - 在线目录：radio-browser（`limit=10`），仅在选择具体地区时请求；失败回退内置
   - 音量：`service_volume_set/get`；电量：`battery_get_pct_raw/status`
3. **开机直入电台**
   - `lisa_ui_nav_scr_default_set(&radio_scr)` 或开机 `nav_to(RADIO_ID)`
   - 按键：单击换台、双击进菜单、三击返回、长按（退出/关机按需）
4. **移除 AI 助手**（分模块摘除，每摘一块编译验证）
   - `apps-ui/apps/llm/` 的页面注册与 presenter；`lschat` 语音会话；唤醒词；云链路上报
   - 逐步确认依赖：音量/亮度/闹钟/OTA/日志上传等设置页（若需要，改为收音机菜单内的最简实现）
5. **配网方案落地**（按第二节选定 A/B/C）
6. **产物与验收**
   - 整包固件（`res/arcs-mini3/` 分区表 + `adb_download.ps1`）
   - 真机验收：开机进电台、换台有声、菜单可用、复位后仍进电台、内存/稳定性长跑

## 四、风险

- 助手模块被多处引用（配网、OTA、闹钟、亮度、音量、日志上传），摘除需逐项确认，**不可一次性删除**
- `lschat`/云链路初始化在启动流程里，删错会导致启动卡住 → 每步必须真机验证
- 音频焦点：确保没有助手抢占音频；退出场景要停止播放
- 板型：**必须用 `arcs_mini3` 构建与烧录**（3.0.3 起固件版型不匹配会提示重新烧录）
